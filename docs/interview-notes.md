# 设计取舍与答辩要点

- Parquet 解决列式文件读写，Iceberg 提供表级元数据、快照、原子提交、演进与维护。性能提升需要实测。
- HWM 使用到达 batch/source_version。今天收到上个月修订时，按 event_date 追进度会漏掉更新。
- 保留 tombstone 的最大 source_version，避免物理删行后旧更新被当成新键插入。展示活跃事件时过滤删除状态。
- 同版本不同内容不能靠排序随意选择，隔离并暂停本批。不同版本以可信源版本比较，不能拿 event_time 排修改顺序。
- audit branch 能隔离数据写入，不能隔离所有表元数据或替代发布协议。分叉需检测后重建，不能无条件 fast-forward。
- 三张表连续提交不是跨表事务；消费者按同一 release 绑定三个 snapshot_id，避免混合明细/汇总版本。
- 日常接入可以继续，但同表更新会排队。本版数据集锁更保守，报告排队时间，不声称无影响的在线补数。
- 快照回滚可能移除后续合法提交。先消费者回退缓解，再以最新 HWM 前向修正，必要时停写回滚加重放。
- 小文件可能来自低频率小批写入、高基数分区和高并行度；目标文件大小不等于结果大小。合并成本要计入。
- benchmark 固定数据、查询、并行配置，预热后重复测量；保留负收益，记录缓存和顺序影响，不把小样本结果外推。
- 代码用分布式 EXCEPT ALL 和落盘差异避免 collect 全表；manifest 清单仍驻 driver，规模增长后需要分片分页。
- 已发布 tag 和审计分支长期保留，会增加存储；原始/中间/湖表多份数据都要进入容量预算。快照不是对象与 catalog 备份。

简历描述使用 docs/acceptance.md 的实际记录数与 benchmarks 实测值。10.157 GiB 是本机三 Worker
的合成宽事件存储/性能专项，不能写成完整 SaaS 业务迁移；云费用是情景估算，不能写成真实账单降本。
50–100 GiB 和生产事故经历仍未取得对应证据。
